01 / 先建立直觉

它准备放置场地，然后才能放单元

网表描述连接，LEF 提供物理尺寸。这个命令根据它们设置 die，并在 core 内建立 rows。一个单元通常横跨多个 site。

Die / 芯片边界

整个芯片的轮廓。矩形坐标写成左下角与右上角。

Core / 核心区域

请求生成 rows 的范围。实际行边界会受到取整影响。

Site / 放置格子

由 LEF 定义宽高。Nangate45 示例为 0.19 × 1.4 µm。

Row / 放置行

多个 site 横向重复。一行记录起点、方向、数量和步长。

最直观的方式：显式给坐标

在 src/ifp/test 目录准备右侧输入。四个坐标的顺序是 {llx lly urx ury}，单位均为 µm。

这里的 die 为 1000 × 1000 µm，core 为 800 × 800 µm。Tcl 中要用花括号把坐标组成一个参数。

来源：init_floorplan1.tcl。site 名必须与已加载的 LEF 一致。

read_lef Nangate45/Nangate45.lef
read_liberty Nangate45/Nangate45_typ.lib
read_verilog reg1.v
link_design top

initialize_floorplan \
  -die_area {0 0 1000 1000} \
  -core_area {100 100 900 900} \
  -site FreePDK45_38x28_10R_NP_162NW_34O

make_tracks
初始化会清除旧 tracks，并删除、重建旧 rows。需要布线轨道时，在它之后执行 make_tracks。这个阶段尚未完成单元布局、引脚安排或电源网格生成。

30% 的目标，为什么得到约 37.2%？

把输出和 DEF 对起来

默认算例得到 3 行 × 52 个 site。它们占用的外包框面积为 41.496 µm²，小于连续目标的 51.427 µm²。

aspect_ratio = 高 / 宽。比例大于 1 表示高而窄，当前 C++ 允许它。利用率输入为百分数，而源码日志中的 0.372 是比值，换算后约为 37.2%。

04 / 从一类行到复杂场地

附加参数会改变哪些行为？

选项用途需要注意
-core_space单值用于四边；四值为下、上、左、右。利用率模式显式提供。可为 0；不能与显式 die 混用。
-row_parity普通行的生成数量约束为 NONE / EVEN / ODD。只减不加；分割后的 row 对象总数未必保持奇偶性。
-flip_sites指定普通 site 以 FS 开头，交替 FS / N。FS 是 MX，关于 x 轴镜像；它不会生成电源网格。
-additional_sites提前为其他 site 准备 rows。普通路径要求高度是基础 site 高度整数倍；x 步长用基础 site 宽度。
-gap已定义电压域周围的留白。不是相邻普通行间距。默认 6 倍最小 site 高度；显式值转 DBU 后须为正。
多高度 rows 与 hybrid rows 有什么区别？

多高度流程为各 site 生成对应高度的候选 rows；hybrid 流程由基础 site 的 ROWPATTERN 指定子 site 与方向，使用模式匹配决定偏移。矩形 hybrid 路径不支持非 NONE 的 row_parity，且不使用普通行的 flipped_sites 参数。多边形路径暂不支持 hybrid rows。

“Core area” 就是最终可用放置面积吗？

普通单 site、无裁行的矩形算例可以这样计算。通用情况下，reportAreas() 使用 getCoreArea() 的外包矩形面积；生成器记录 core 的时点又早于电压域与障碍物裁行。对有缺口、孔洞或行分割的场景，日志面积不等于最终可用 site 面积总和。

参数写错后，原 floorplan 会自动恢复吗？

不能这样假定。Tcl 先建 die，再解析和生成 rows；部分错误可能发生在 die 已改变、tracks 已删除之后。普通 rows 的某些后续检查也发生在旧 rows 被删除后。试验不同参数时，可重新读取设计或启动独立进程。

源码校验与推荐输入范围有哪些差异？

推荐 0 < utilization ≤ 100，aspect_ratio > 0。当前 C++ 对 utilization 只显式检查非负，缺少完整的零值和上限保护；教学计算器限制有效输入。不要把校验遗漏理解为支持异常参数。帮助里的 -site 虽带方括号，建行 helper 实际仍要求它。

05 / 多边形与扫描线

同一个高度，可以生成多个 row 片段

die 或 core 任一列表超过 4 个坐标就进入多边形分支。两者都需要提供至少 4 个顶点；坐标数要为偶数。轮廓应为简单正交多边形，core 应位于 die 内。

简化坐标模型：core 轮廓，site 为 10 × 10；拐点对齐行高。此图不使用 Nangate45 尺寸，不模拟 die 系统障碍物或 UPF。

交点排序 → 两两配对 → 对齐格子

# 已加载库、网表，并 link_design
initialize_floorplan \
  -die_area {0 0 200 0 200 100
             100 100 100 200 0 200} \
  -core_area {20 20 180 20 180 80
              80 80 80 180 20 180} \
  -site FreePDK45_38x28_10R_NP_162NW_34O

可在仓库测试数据环境运行的 L 形例子；左侧演示用独立的简化尺寸。源码：makeUniformRowsPolygon / intersectRowWithPolygon。

当前 intersectRowWithPolygon() 用的是 row 底边 y，并未对整行高度做严格多边形相交；拐点落在一行中间时，不能只凭这次求交断言整行都在 core 内。另一个边界是：显式包含检查使用 die/core 的外包框，并非完整多边形包含检查。

OpenDB 还会将“die 外包框减去 die 多边形”的空白区转换为系统障碍物，供后续裁行使用。core 缺口和 die 外部空白区是两回事，不能认为这一步自动完成了所有 core 几何校验。
