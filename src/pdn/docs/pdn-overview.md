# PDN 模块总览：为电路铺设供电网络

`pdn`（Power Distribution Network，电源分配网络生成器）根据工艺、平面规划和供电策略，生成电源与地的金属网络，包括电源环、条带、行内电源轨及层间过孔。OpenROAD 中的实现源于 PDNGEN。

本文依据 OpenROAD 提交 `a5a08e8356` 的文档与源码编写。具体策略配置见 [PDN README](../README.md)。

## 1. 为什么供电也需要专门设计？

逻辑网表主要说明信号如何传递。所有单元要工作，还必须从外部电源获得能量，并有地线回路。电源金属不是理想导体，电流经过它会产生电压损失；局部通路过窄还可能承受过大的电流密度。

把供电想成供水管网：上层较粗的干线负责输送，较细的支路把供给送到各个用电单元。线路越密、越宽，通常越有利于降低供电阻抗，但也会占用信号布线所需的金属空间。

PDN 的任务是把“使用哪些层、条带多宽、多密、怎样连接宏块”等策略变成具体几何。电压降是否合格，要通过 `psm` 等分析再判断。

## 2. 输入和输出

| 输入 | 用途 |
| --- | --- |
| 工艺层、过孔和相关几何规则 | 确定可制造的线宽、间距和跨层连接。 |
| OpenDB 中的 floorplan、放置行和宏块位置 | 知道在哪些区域生成网格，以及引脚和障碍在哪里。 |
| 电源、地网络及引脚归属 | 确认哪些单元电源引脚应该连接到哪个供电网络。 |
| 电压域与区域关系 | 区分共享供电和独立供电的范围，支持多域设计。 |
| 网格策略 | 指定层、宽度、间距、节距、偏移、环、条带和跨层连接方式。 |

主要输出是**OpenDB 中电源与地网络的 special wires 和过孔等实体结构**，以及生成和连接检查中的相关信息。Special wires 是数据库中表示这类专用布线的对象，不是只画在 GUI 上的辅助线。

需要区分两件事：把引脚在逻辑上归到 `VDD` 网络，并不等于已经有金属将它接通；两条不同层的电源线在平面图上相交，也必须有合适的过孔才能导通。

## 3. 供电网格由哪些部分组成？

| 结构 | 可以怎样理解 | 主要作用 |
| --- | --- | --- |
| Ring：电源环 | 围绕核心区或宏块的环形干线 | 在区域周边组织供电连接。 |
| Strap / stripe：条带 | 横向或纵向铺开的供电干线 | 在区域内部输送电流。 |
| Followpin rail：行内电源轨 | 顺着标准单元行和电源引脚排列的细支路 | 把网格接到行内单元。 |
| Via：过孔 | 不同金属层之间的垂直连接 | 将各层网格连成完整通路。 |
| 宏块专用网格 | 适应宏块位置、方向和电源引脚的连接结构 | 连接宏块与上层或周边供电网络。 |

这些结构不要求每个设计全部具备，取决于封装供电方式、宏块和工艺资源。电源通常从 pad、bump 或设计块的供电端口进入，相关连接必须与系统供电方案一致。

## 4. 核心工作与典型场景

```mermaid
flowchart LR
    A[供电网络与区域] --> B[定义网格策略]
    B --> C[生成环和条带]
    C --> D[避让障碍并构建过孔]
    D --> E[写回电源几何]
    E --> F[PSM 检查连通与压降]
    F --> B
```

生成器按照策略铺设金属，并处理宏块、既有形状和层规则对网格的影响。在需要连通的层间生成合适的过孔，修剪或调整部分形状，输出无法实现的连接等诊断信息。

**单电源域标准单元设计。** 从覆盖核心区的网格和行内电源轨开始，检查主干到单元引脚是否形成连续通路。

**带存储器宏块的设计。** 宏块可能阻挡低层金属，而且自身电源引脚位于指定层和边界。需要专门的宏块网格或连接策略，不能假定标准单元的行内电源轨也能连接宏块。

**多电源域或可关断区域。** 不同供电网必须保持正确归属。电源开关及其上下游网络、域边界和供电网格需要协调，避免把本应独立的供电直接短接。UPF 提供部分电源意图，PDN 负责对应物理结构。

例如，宏块与核心区的两段电源条带看起来相交，却因可用重叠面积太小，无法容纳满足包围规则的过孔。此时需要调整网格或宏块连接方案，单看金属覆盖图容易误判。

## 5. 怎样判断结果有用？

先检查连通性：有没有悬空条带、遗漏的单元电源引脚或层间断点。再通过 PSM 检查在给定电源位置和负载下的电压降及电流分布，最后结合信号布线观察资源占用是否合理。

**网格生成成功、供电连通、电压降合格，是三个不同层次的结论。** 更密的网格可能改善压降，却也可能让信号布线变差，因此应在供电、面积和布线质量之间迭代。

PDN 规划通常在 floorplan 和宏块位置已有依据时进行；其结果会成为后续布局、引脚安排和布线需要考虑的物理环境。具体生成时机和补充连接步骤由流程决定。

## 6. 三类角色的后续学习路径

- **OpenROAD 工具使用者：** 先看 [README](../README.md) 的网格示例，再从 [测试目录](../test) 选择核心网格和宏块网格案例。用 GUI 检查一次从上层电源到单元引脚的完整通路，再结合 [PSM 总览](../../psm/docs/psm-overview.md) 学会验证压降。
- **OpenROAD 其他模块开发者：** 阅读 [PdnGen.cc](../src/PdnGen.cc)、[domain.cpp](../src/domain.cpp) 和 [grid.cpp](../src/grid.cpp)，理解供电归属、区域和 special wires。布局或布线模块需要正确处理这些形状对可用资源的影响。
- **PDN 模块开发者：** 进一步阅读 [straps.cpp](../src/straps.cpp)、[rings.cpp](../src/rings.cpp)、[connect.cpp](../src/connect.cpp) 和 [via.cpp](../src/via.cpp)。重点验证宏块方向变换、窄通道、跨层连接及多域场景，同时考察 PSM 连通性和后续路由结果。
