# GRT 模块总览：为连线规划路径和资源

`grt`（Global Routing，全局布线）在单元和引脚位置已知后，规划各条网络大致经过哪些区域、使用哪些金属层，并协调它们对布线资源的竞争。它生成的路径与布线引导，是详细布线的重要输入。

本文依据 OpenROAD 提交 `a5a08e8356` 的文档与源码编写。配置说明见 [GRT README](../README.md)。

## 1. 为什么不能直接按最短距离连线？

网表中的一条 net，表示需要电气连通的一组引脚。芯片上可能有大量这样的网络，它们要共享有限的金属层和通道。分别为每条网络选择最短路径，容易让许多导线集中在同一处，而其他区域空闲。

GRT 像交通路线规划：先分配各条连接所经过的走廊，让整体需求尽量不超过走廊容量。至于走廊内具体使用哪条轨道、每个转弯和过孔怎样满足工艺规则，由后续 `drt` 处理。

| 概念 | 含义 |
| --- | --- |
| GCell | 全局布线使用的较粗空间网格单元，不是逻辑单元。 |
| 容量（capacity） | 相邻网格之间可供布线使用的资源估计。 |
| 需求（demand） | 已规划路径对这些资源的占用。 |
| Overflow | 需求超过容量的部分，表示全局布线模型中的超载。 |
| Route guide | 每条网络允许或建议经过的带层信息的区域，供详细布线使用。 |

## 2. 输入和输出

| 输入 | 用途 |
| --- | --- |
| OpenDB 中的网表及已放置引脚 | 确定需要连接的端点、位置和物理形状。 |
| 金属层、轨道和障碍信息 | 构建分层布线网格及其容量。 |
| 电源网络、宏块等已占资源 | 修正实际可用通道；电源线也占用金属资源。 |
| 可用层范围、容量调整和网络选择 | 表达流程希望保留的余量及本次路由范围。 |
| 启用相关优化时的时序信息 | 支持优先处理关键连接或配合后续优化。 |

主要输出包括**全局路径段、route guides、拥塞与线长统计**。路径信息可保存在内存、数据库或相应文件中，再由后续模块使用。

全局路径还能为寄生参数估计提供比纯布局距离更具体的依据；相应估计操作依然需要按流程执行。GRT 的结果不是最终金属形状，也不是完整设计规则检查通过的证明。

## 3. 核心工作：建网格、选拓扑、分配路径

```mermaid
flowchart LR
    A[端点、层和障碍] --> B[建立资源网格]
    B --> C[构建网络连接拓扑]
    C --> D[分配路径与层]
    D --> E[评估拥塞]
    E --> F[拆线重布]
    F --> D
    E --> G[输出 guides 与路径]
```

**把几何空间转换为容量图。** 宏块会阻断部分区域，电源金属会占用轨道，部分层也可能被保留给特定用途。容量模型的准确性直接影响结果是否过于乐观。容量调整是为详细布线预留余量的手段，会改变规划时可使用的资源。

**为多端点网络选择连接拓扑。** 一条网络可以有一个驱动端和多个负载端。共享部分干线通常比每个负载单独拉线更节省总线长，Steiner 树可提供这样的初始结构。`stt` 为这类工作提供基础构树算法。

**在资源图上安排路径。** 路径选择综合长度和拥塞等代价，必要时绕行；金属层分配还需要考虑各层方向、容量和跨层连接。总线长更短的方案，不一定具有更好的可布线性或时序。

**拆除冲突路径并重新规划。** Rip-up and reroute 即拆线重布：对资源竞争严重的区域提高代价，使部分网络选择其他路径。它是一个相互影响的过程，单独改善一条网络可能改变其他网络的资源条件。

当前模块主要基于 FastRoute；源码也集成了 CUGR 选项，但本版本 README 将其标为尚不适合生产使用。理解 GRT 的公共职责后，再学习具体求解器的差异更有效。

## 4. 典型场景与结果判断

**给详细布线生成引导。** 标准单元与时钟网络已有合法位置后，运行全局布线，确认路径与拥塞情况，再交给 DRT 落实。

**提前发现布局问题。** 某个宏块通道持续高 overflow，可能说明连接需求超过物理容量。可尝试调整层或容量设置，但也可能必须移动宏块、分散单元或改变 floorplan。

**更新时序估计。** 某条关键路径在布局阶段看起来很短，全局布线却必须绕过宏块。基于这条实际规划路径更新寄生估计后，STA 才能更好地反映绕行影响，RSZ 也能据此修复。

结果至少要检查 overflow 的位置和总量、路径长度、过孔使用趋势、时序变化，以及 DRT 是否顺利完成。**全局 overflow 为零仍可能存在引脚无法接入、局部间距冲突或过孔放不下的问题。** 这些细节超出了粗网格容量模型。

## 5. 与其他模块如何协作？

| 模块 | 与 GRT 的关系 |
| --- | --- |
| `gpl` | 可调用路由反馈评估布局拥塞。 |
| `dpl` / `cts` | 决定本次布线所用的单元和时钟引脚位置。 |
| `stt` | 提供初始连接拓扑及线长、路径深度权衡。 |
| `rsz` / `sta` | 利用路径和寄生估计分析、优化时序；电路变更后可能需更新布线。 |
| `drt` | 消费 guides，生成实际线段和过孔。 |

## 6. 三类角色的后续学习路径

- **OpenROAD 工具使用者：** 用 [README](../README.md) 的示例和 [测试目录](../test) 学习观察拥塞图，比较布线层范围或容量预留改变前后的路径。继续运行 DRT，以其完成度验证全局指标的预测能力。
- **OpenROAD 其他模块开发者：** 从 [GlobalRouter.cpp](../src/GlobalRouter.cpp)、[Grid.cpp](../src/Grid.cpp) 和 [Net.cpp](../src/Net.cpp) 理解数据库对象、路由网格及路径的转换。重点确认引脚或连接修改后，哪些路由和寄生信息已经失效。
- **GRT 模块开发者：** 进入 [FastRoute.cpp](../src/fastroute/src/FastRoute.cpp)、[RSMT.cpp](../src/fastroute/src/RSMT.cpp) 及 [maze.cpp](../src/fastroute/src/maze.cpp)，研究构树、路径搜索和拥塞迭代。评价修改时同时跟踪详细布线违例、最终时序、线长、过孔和运行时间。
