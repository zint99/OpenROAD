03 / DISTINCTIONS / timing & routability
04 / 07

有些排序已稳定，
顺序仍能从其他路径进入。

TIMING

固定 slack，权重不随排列改变

net 已按 slack + ID 排名，再按各自 slack 查询权重；修复 driver 也按 level + name 排序。

24

四个 net 的全部输入排列
得到相同权重

slack map → cutoff → weight(net)

完整流程仍受上游电容的 float 累加、
公共布局坐标和梯度影响。

ROUTABILITY

默认 RUDY 存在跨 net 累加

同一 tile 的需求按 ODB net 顺序以 float 累加；舍入差异接近阈值时可改变反馈决策。

net₁ + net₂ + … → tile demand
→ congestion → inflation / revert

可选同分 net 加权：可能选中不同对象。
GRT pin 去重：可能改变物理 root。

边界：net 加权默认关闭；GRT net 总表已按名称排序，root 的路由影响取决于配置。

固定输入的内核独立性，与整个功能的结果独立性，需要分别判断。完整研究 §5–6 ↗

06 / NEXT STEP / 行动建议
07 / 07

把顺序不变性作为独立目标，
用对照实验界定影响。

01

建立一致基线

选取代表设计，构建与源码一致的二进制；固定对象 ID、几何、约束、线程和 seed。

产出
可重复运行的设计与配置基线
02

隔离顺序变量

在消费边界分别置换 instance、net、pin；逐项比较原序、逆序和固定 seed 的 shuffle。

产出
最早分岔位置 + 最终 QoR 差值
03

按证据选择修复点

稳定同分选择、绑定实例扰动身份，再评估浮点归约的规范化及其运行成本。

产出
修复收益、性能成本与回归约束
