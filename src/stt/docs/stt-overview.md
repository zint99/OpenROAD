# STT 模块总览：为多个引脚设计共享的连接树

`stt`（Steiner Tree）根据引脚坐标，为一条多端点网络构建几何连接树，帮助上层模块估计线长或生成初始路由拓扑。它是一项基础算法服务，通常由其他模块调用，而不是独立完成一次布线流程。

本文依据 OpenROAD 提交 `a5a08e8356` 的文档与源码编写。配置说明见 [STT README](../README.md)。

## 1. 为什么连接多个引脚要“构树”？

假设一个驱动端要连接三个接收端。可以从驱动端分别拉三条线，也可以先走一段共享干线，再在途中分支。不同连接方式具有不同的总线长和到达各接收端的路径长度。

芯片连线常用水平、垂直线段组织，因此会研究**直角 Steiner 树**：在给定端点之外，允许增加只用于分支的几何点，尽量以较短的总长度连接全部端点。

```text
端点：A=(0,0)，B=(4,0)，C=(2,3)

        C
        |
        | 3
        |
 A--2---S---2--B
```

S 是新增的 Steiner 分支点。这个示意树的总长度是 `2 + 2 + 3 = 7` 个坐标单位。若只允许以原有端点作为树节点，端点间曼哈顿距离为 AB=4、AC=5、BC=5，最小生成树的边权总和为 9。允许增加分支点提供了更灵活的共享方式。

这里的 S 是几何连接点，不代表插入了一个缓冲器，也不是新增逻辑门。

## 2. 输入和输出

| 输入 | 作用 |
| --- | --- |
| 一组端点的平面坐标 | 定义需要相连的位置。 |
| 驱动端索引 | 对需要考虑源到负载路径的算法，说明信号从哪里出发。 |
| 构树参数或网络级配置 | 控制总线长与路径长度之间的权衡。 |
| 相关调用中的网络对象 | 用于选择该网络的配置；基本几何构树接口也可直接处理坐标。 |

输出是**包含端点、分支点和邻接关系的树结构**，供调用者计算长度、遍历分支或继续安排路由。

输出中的一条分支描述连接关系。若两个节点的横纵坐标都不同，其曼哈顿长度可直接估计，但具体先横后竖还是先竖后横，以及选层、选轨道和过孔，仍需要后续处理。

## 3. 两类重要算法与权衡

| 方法 | 主要关注什么 | 如何理解 |
| --- | --- | --- |
| FLUTE | 快速构造低总线长的直角 Steiner 树 | 通过查表和分解等方法，为路由提供高效的几何连接结构。 |
| Prim–Dijkstra | 总树长与驱动端到负载的路径长度之间的权衡 | 既考虑共享连接，也避免某个负载沿树绕行过远。 |

**总线长短，有利于减少总体布线和电容负担。** 但对某个负载而言，沿共享树从驱动端走到它的距离可能仍很长。

**源到负载的路径短，有利于限制某些传播路径。** 代价可能是减少共享、增加总线长。Prim–Dijkstra 的 alpha 参数表达这一权衡：较小值偏向总长度，较大值偏向驱动端到负载的路径。它是几何启发式，不等同于完整的 RC 时序优化，也不保证任意输入都达到理论最优。

当前 [SteinerTreeBuilder.cpp](../src/SteinerTreeBuilder.cpp) 中，带 alpha 的接口在 alpha 大于零时尝试 Prim–Dijkstra，并在相关树检查未通过时回退到 FLUTE；另有直接走 FLUTE 的接口。**具体使用哪条路径取决于调用接口和配置**，不宜把整个模块概括成永远只用一种算法。

## 4. 它能解决什么，还没有解决什么？

典型场景是 GRT 为多引脚网络建立初始拓扑。上层先获得一棵较好的共享连接树，再根据实际拥塞和金属层容量把各分支变成路径。

另一个场景是对构树算法进行比较：固定同一组端点和驱动端，观察不同 alpha 下的总树长、最长源到负载路径和运行时间。高扇出网络尤其容易显示这类取舍；扇出指一个驱动端所驱动的负载数量。

基础 STT 构树接口并未同时解决完整的障碍避让、层容量、引脚接入和设计规则问题。若几何最短树穿过宏块，上层路由器仍需改道。也不能把树的总长度直接当成最终 RC 延迟：不同层、负载和缓冲方式会改变电气结果。

## 5. 与相邻模块的关系

```mermaid
flowchart LR
    A[布局提供引脚位置] --> B[STT 构建连接拓扑]
    B --> C[GRT 按容量规划路径]
    C --> D[DRT 落实轨道与过孔]
    D --> E[寄生提取与时序分析]
```

这是一条典型用途链，STT 本身只是其中的几何构树环节。它也不同于 CTS：CTS 会插入真正的时钟缓冲器并平衡时钟电气特性，STT 的分支点只是连接结构。

对 STT 本身，应检查端点是否全部连通、结果是否为合法树、驱动端身份是否正确，以及重复坐标等边界情况。对整个实现流程，还要观察该树是否帮助最终布线与时序改善。

## 6. 三类角色的后续学习路径

- **OpenROAD 工具使用者：** 先理解共享干线与路径绕行，再结合 [README](../README.md) 调整小网络的 alpha。比较总线长与最长源到负载路径，随后用 GRT/STA 确认几何改善是否带来实际收益。
- **OpenROAD 其他模块开发者：** 阅读 [SteinerTreeBuilder.h](../include/stt/SteinerTreeBuilder.h) 和 [SteinerTreeBuilder.cpp](../src/SteinerTreeBuilder.cpp)，掌握坐标单位、驱动索引、分支表示及回退路径。接入时特别检查重复端点和零长度分支的处理。
- **STT 模块开发者：** 深入 [FLUTE 实现](../src/flt) 与 [Prim–Dijkstra 实现](../src/pdr/src/pd.cpp)。从 [flute1.tcl](../test/flute1.tcl)、[pd1.tcl](../test/pd1.tcl) 和 [pd2.tcl](../test/pd2.tcl) 学习小规模、重复坐标和驱动索引案例，再评估高扇出输入的质量及耗时。
