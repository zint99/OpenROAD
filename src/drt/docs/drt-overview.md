# DRT 模块总览：把连接落实为具体的金属线和过孔

`drt`（Detailed Routing，详细布线）根据引脚、布线引导和工艺规则，为网络生成实际金属线段与过孔，并反复检查、修复布线冲突。OpenROAD 的详细布线器基于 TritonRoute。

本文依据 OpenROAD 提交 `a5a08e8356` 的文档与源码编写。命令说明见 [DRT README](../README.md)。

## 1. 为什么全局路径还不够？

全局布线说明一条连接大致经过哪些区域。制造所需的版图还必须明确：导线在什么层、什么坐标，线宽多少，如何进入引脚，在哪里通过过孔切换金属层，以及与邻近导线保持多大距离。

例如，某条走廊整体容量足够，但目标单元的引脚很窄，附近还有另一条导线。路径到达这个区域后，可能没有合法的过孔或接入方向。因此，“有地方经过”与“能按规则接到引脚”是两个不同层次的问题。

| 概念 | 含义 |
| --- | --- |
| Track（轨道） | 金属层上用于组织布线的参考位置。 |
| Via（过孔） | 连接不同金属层的导电结构，也有尺寸、间距和包围规则。 |
| Pin access（引脚接入） | 找到导线或过孔进入引脚的合法位置与方式。 |
| DRC | Design Rule Check，设计规则检查，例如宽度、间距、最小面积和过孔规则。 |

## 2. 输入和输出

| 输入 | 提供什么 |
| --- | --- |
| 已布局且应保持一致的网表 | 每条网络必须连接的端点及其当前位置。 |
| 工艺 LEF、单元引脚和障碍形状 | 描述可用层、几何规则和需要避让的对象。 |
| 全局布线 guides | 限定或引导路径搜索的主要区域与层。 |
| 已存在的电源金属等物理结构 | 构成布线环境中的固定资源占用。 |
| 布线范围及求解配置 | 控制可用层、迭代方式及相关接入策略。 |

主要输出是**写回 OpenDB 的实际布线线段、过孔及相关补充金属形状**，并产生连接和 DRC 等报告。设计可随后保存为数据库或 DEF 等格式，继续进行寄生提取、时序分析及后续验证。

DRT 内部会使用专门的数据结构处理几何和搜索，读入、转换、写回也是完整实现的一部分。用户看到的最终数据库应与布线器的结果一致。

## 3. 核心工作：先接得上，再反复修规则

```mermaid
flowchart LR
    A[设计与 guides] --> B[引脚接入分析]
    B --> C[轨道分配]
    C --> D[初始详细布线]
    D --> E[规则与连接检查]
    E --> F[搜索、拆线与修复]
    F --> E
    E --> G[写回布线结果]
```

**引脚接入分析。** 寻找各个引脚可用的接入点及过孔组合，还要考虑相邻实例之间的相互影响。某些后期布线困难，其根源其实是布局阶段把难接入的引脚挤得太近。

**轨道分配。** 在 guides 提供的较粗路径区域内，先把连接组织到更具体的轨道上，为详细搜索提供起点。它是中间安排，后续仍可能调整。

**详细路径搜索。** 在局部空间中选择线段、转弯和过孔，使同一网络连通。搜索会考虑已有布线和障碍，必要时使用绕行来避开冲突。

**规则检查与修复。** DRC 引擎产生标记，指出哪些几何对象违反了哪些已支持的规则。布线器围绕问题区域拆除、重布或补充金属，再检查是否引入新的冲突。单条网络合法，不代表多条网络合在一起仍合法，因此必须迭代。

工作常被分成多个空间窗口，以控制搜索规模和支持并行。窗口边界如何保持连接完整、如何协调邻近修改，是模块开发的重要问题。

## 4. 典型场景与结果判断

**完成全芯片或设计块的信号布线。** 在全局布线之后落实导线，并把工艺约束应用到具体几何。

**排查持续存在的局部违例。** 如果同一位置反复出现间距或过孔冲突，增加迭代不一定能解决。应查看引脚形状、局部布线空间、guides 和固定障碍，判断问题是否需要回到布局或电源网络规划阶段处理。

例如，两个相邻单元各自都有合法接入点，但同时使用这些点时过孔间距不满足规则。修复可能需要移动路线、选择其他接入方式，甚至在上游给单元增加间距。

| 结果 | 应如何理解 |
| --- | --- |
| 连通性 | 所有应连接的端点是否完成连接；还需关注意外短接。 |
| 剩余 DRC 数量及类型 | 反映当前检查范围内的几何问题；位置和类型往往比总数更能解释原因。 |
| 线长与过孔 | 影响面积占用、寄生参数及后续时序。 |
| 提取后的时序 | 检查实际布线是否仍满足设计约束。 |

DRT 报告零违例，表示其支持的检查范围和当前输入规则下没有发现相应问题。完整制造规则验证仍要按项目采用的签核流程完成；布线成功也不自动意味着时序满足要求。

## 5. 与其他模块如何协作？

`grt` 提供 guides；`dpl` 决定引脚的相对位置；`pdn` 已生成的供电金属影响可用空间。布线之后，寄生提取模块如 `rcx` 可提取导线 RC，`sta` 再据此分析时序。若上游修改单元或连接，相关路由也需要按流程重新处理。

## 6. 三类角色的后续学习路径

- **OpenROAD 工具使用者：** 从 [测试目录](../test) 学习查看路由结果和 DRC 标记，选择一个具体违例，解释它涉及哪些线段、引脚或过孔。把“加迭代”与“改善上游空间”两种方法的效果进行比较。
- **OpenROAD 其他模块开发者：** 阅读 [TritonRoute.cpp](../src/TritonRoute.cpp) 与 [io 目录](../src/io)，掌握 guides、数据库和内部设计对象之间的接口。若开发布局或电源模块，应通过 pin access 和局部 DRC 检查评估对布线的影响。
- **DRT 模块开发者：** 沿 [pa](../src/pa) → [ta](../src/ta) → [dr](../src/dr) → [gc](../src/gc) 阅读引脚接入、轨道分配、详细搜索与几何检查。以局部最小案例定位规则错误，再用完整设计评估连接正确性、违例、运行时间和最终时序。
